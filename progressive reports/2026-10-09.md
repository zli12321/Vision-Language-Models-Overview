# Progressive Research Report — October 9, 2026

> **Focus:** Releases and material updates from **GPT, Claude, Qwen, Kimi, DeepSeek, Tencent Hunyuan, Gemini, and GLM**. The main reporting window is **September 14–October 9, 2026**, following the [September 13 report](2026-09-13.md). Earlier releases omitted or incompletely described in the survey are explicitly marked **catch-up**.
>
> **Method:** Official announcements, developer changelogs, author papers, repositories, and model cards, checked on October 9. A model launch, a paper publication, a new hosting option, and an API change are different events. “Open weights” means downloadable checkpoints; the applicable license is listed where verified. Performance claims remain vendor-reported. This is a targeted review of major families, not an exhaustive release census.

The main developments are a new round of GPT and Claude releases, Qwen's multimodal-agent and image-generation updates, DeepSeek's V4.1 architecture disclosure, and Tencent's new image preview. Several important open-weight releases also need to be caught up in the survey. **The strongest disclosed architecture changes concern attention, memory, residual connections, and the separation of input processing from output generation.** Closed-model capability improvements generally do not come with comparable internal detail.

## 2. GPT and Claude

### GPT: new models and changes to existing endpoints

**GPT-6 Sol and Luna launched September 22; GPT-6.1 Sol followed September 29.** They extend the hosted frontier lineup for image understanding, document work, and agent execution. OpenAI reports that GPT-6.1 Sol improves over GPT-6 Sol by **7 percentage points** on its OSWorld 2.0 offline evaluation at maximum effort. That is a **partial-reward result on the v2026.08.08 offline set**, so it should not be mixed with strict-success scores from other OSWorld protocols. [Sol/Luna release](https://openai.com/index/introducing-gpt-6-sol-and-luna/), [6.1 Sol release](https://openai.com/index/introducing-gpt-6-1-sol/).

**Catch-up:** [GPT-6 Astra](https://openai.com/index/gpt-6-astra/) launched **September 3**, before the previous report. It belongs in the frontier-model catalogue, with its release date preserved. Architecture, parameter counts, and vision-encoder details remain undisclosed for these GPT releases.

The [official API changelog](https://developers.openai.com/api/docs/changelog) also records changes that affect deployment or reproducibility without constituting new foundation models:

| Date | Change | Why track it separately? |
|---|---|---|
| **09/25** | Image-encoding fix for GPT-6 Sol / Luna | Visual results can depend on the evaluation date or snapshot. |
| **10/06** | Decisions API beta with GPT-6 Luna | A structured decision interface for text/images; not evidence of a new backbone. |
| **09/29; 10/08** | Astra Ultrafast and GPT-6.1 Sol Ultrafast availability | Serving/latency changes, distinct from model architecture. |

### Claude: 5.5 across three tiers, plus an earlier frontier release

**Opus 5.5 (September 22), Sonnet 5.5 (September 28), and Haiku 5.5 (October 7)** are the main in-window releases. Their VLM relevance includes visual analysis, image understanding, and browser/computer interaction. The useful comparison is capability against latency and cost for a fixed task and reasoning budget; the announcements do not disclose an encoder or fusion redesign. [Opus](https://www.anthropic.com/claude-opus-5-5), [Sonnet](https://www.anthropic.com/claude-sonnet-5-5), [Haiku](https://www.anthropic.com/claude-haiku-5-5).

**Catch-up:** Anthropic's [newsroom](https://www.anthropic.com/news) dates **Fable 5.1 / Mythos 5.1 to September 1**. The [release page](https://www.anthropic.com/claude-fable-and-mythos-5-1) describes the same underlying model with different safeguards: Fable is generally available, while Mythos uses trusted-access programs. It also reports computer-use results. These are relevant frontier releases, but two access configurations should not be treated as proof of two independently designed architectures.

## 3. Qwen

**Qwen3.8-Omni-Flash — September 18 launch; September 22 technical report.** The model builds on Qwen3.8-Next sparse MoE and supports a **1M-token context**. Its contribution is native multimodal co-training and agent workflows across text, audio, and video. The released **Qwen-MM-Plugins** and **Qwen-Live-Harness** are open tooling; they do not establish that the hosted model's weights are open. Likewise, a workflow that invokes video-production tools does not establish a native video-generation head. [Announcement](https://qwen.ai/blog?id=qwen3.8-omni-flash), [technical report](https://arxiv.org/abs/2609.25611).

**Qwen-Image-2.1 — September 20.** This is an actual downloadable image-generation/editing release. It unifies ordinary and transparent **RGBA** image creation and editing, with up to **10 reference images**. Its **7B visual generation component** uses 32 single-stream DiT layers, mixed-granularity attention, and prefix KV-cache reuse. The 7B number describes that component, not necessarily every component loaded by a complete pipeline. The [model card](https://huggingface.co/Qwen/Qwen-Image-2.1) labels the weights **Qwen Research**, so do not copy an Apache-2.0 assumption from other Qwen releases. [Dated release log](https://github.com/QwenLM/Qwen-Image-2.1).

**Architecture catch-up: Qwen3.8-Flash-Next — August 26.** The [official repository](https://github.com/QwenLM/Qwen3.8-Flash-Next) positions it as an early preview of the architecture intended for Qwen4, not a release of the full Qwen4 family. It combines **Gated DeltaNet + Qwen Sparse Attention**, widened **Gated Residual** streams, and offloaded **n-gram embedding memory**. The [August 31 paper](https://arxiv.org/abs/2608.30320) specifies **125B main-model parameters / 6B active, plus 51B n-gram embeddings**; the [model card](https://huggingface.co/Qwen/Qwen3.8-Flash-Next) additionally lists **4B MTP**. It has a vision encoder, 262,144 native context extensible to 1M, and **Qwen Community License 1.0** weights. Avoid collapsing these component counts into “125B total.”

The smaller **Qwen3.8-27B** is another catalogue catch-up: the [official series repository](https://github.com/QwenLM/Qwen3.8) dates it to **August 14**. It is a useful dense-model comparison point, distinct from Flash-Next and the hosted Omni branch.

## 4. DeepSeek

**V4.1-Flash is the largest architecture omission in the previous report.** It launched **September 10**; the [technical report](https://arxiv.org/abs/2609.19969) appeared **September 17**. It supports image/text input and autoregressive text output, with API access and [MIT-licensed weights](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash).

The **Causal Encoder–Decoder (CED)** uses a 20-layer causal encoder and a 20-layer decoder. Decoder global KV states are projected from the encoder's final states. This lets input prefill use **8B active parameters**, versus **16B during decoding**. The advertised **552B is the backbone count**; the model card separately describes **196B Engram memory**, so 552B should not be labeled the complete checkpoint total. Native multimodal training still uses **DeepSeek-ViT and an MLP projector**. [Architecture and component accounting](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash).

**CSA2** shares compressed KV states and sparse indices across layers; together with low-bit cache storage, the design targets long-context memory costs. DeepSeek reports roughly **one-quarter the HBM cache and one-eighth the persistent SSD cache** of the previous Flash generation. Those are cache-footprint claims, not equivalent reductions in total model memory or end-to-end latency. [Technical report](https://arxiv.org/abs/2609.19969), [announcement](https://www.deepseek.com/en/news/deepseek-v4-1-flash/).

**Operational update within this reporting window:** from **September 14, 04:00 UTC**, `deepseek-v4-pro` requests route to V4.1-Flash, according to the announcement. The old Flash and experimental vision aliases also route to it. Evaluations must record the actual served model and date; an unchanged API name can now mean a different model. The announcement's reference to a future **V4.1-Pro** is not evidence that it has launched. [API migration notice](https://www.deepseek.com/en/news/deepseek-v4-1-flash/).

## 5. Kimi

**The recent model update is K2.8 Preview for Kimi Code, dated September 11**, just before the reporting window. Moonshot describes stronger coding, more efficient thinking, and 1M context; the `kimi-for-coding` model ID remains unchanged. This is a hosted preview. The release note does not justify inventing a new vision architecture or assuming downloadable weights. **Kimi Code Desktop on September 17** is a product release, while **K3's September 18 Amazon Bedrock launch** expands hosting availability. [Kimi Code changelog](https://www.kimi.com/code/docs/en/kimi-code/whats-new.html), [AWS announcement](https://aws.amazon.com/about-aws/whats-new/2026/09/moonshot-ai-kimi-k3-on-amazon-bedrock/).

**Kimi K3 is a July model, with weights now available.** Its disclosed design combines **Kimi Delta Attention and Gated MLA**, **Attention Residuals**, and **Stable LatentMoE**. The card lists **2.8T total / 104B active parameters** and a **401M MoonViT-V2 vision encoder**, under the custom **Kimi K3 License**. This corrects the README's earlier “no separate vision module” and “weights due” statements. [Official model card](https://huggingface.co/moonshotai/Kimi-K3), [July release history](https://www.kimi.com/code/docs/en/kimi-code/whats-new.html).

No later K3-family foundation-model successor was verified in the official sources reviewed for this update. Product releases and newly added evaluation results are recorded as such.

## 6. Tencent Hunyuan

**Hy Image 3.5 preview — September 22** is the relevant new multimodal release: text-to-image, reference-based generation, and multi-turn editing. The launch announcement specifies up to **five references and 2K output**. It is available through Tencent Cloud and Tencent applications; no downloadable 3.5 weights were verified. Architecture and parameter counts are not disclosed in the announcement. [Tencent Cloud's official launch post](https://news.qq.com/rain/a/20260922A03ZQ000).

**Hy4 preview is an earlier language-model release to catch up.** Tencent's [official collection](https://huggingface.co/collections/tencent/hy4-preview) lists the checkpoint as updated **August 28**; this is checkpoint metadata, not a new October launch. The [model card](https://huggingface.co/tencent/Hy4-preview) describes **770B backbone / 49B active**, plus a separate **10B / 0.7B-active MTP layer**, and a 1M context. Its architecture combines **Gated DSA**, **IndexCache** for sparse-index reuse, and **identity Hyper-Connections (iHC)**. BF16 and FP8 weights are released under **Apache-2.0**.

Keep the branches distinct: Hy4's published interface is a language model; Hy Image 3.5 is an image model. Tencent releasing both does not establish that Hy4 accepts images, or that Hy Image 3.5 inherits Hy4's disclosed architecture.

## 7. Gemini and GLM

### Gemini: live multimodality and a restricted frontier launch

**Gemini 3.8 Live / Live Extended Thinking launched September 15** (announcement updated September 17). The release combines live dialogue, visual grounding, and parallel reasoning/tool execution, with developer access through the Gemini API. It is directly relevant to the shift from answering questions about static images to interacting with live visual context. [Official announcement](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-3-8-live-gemini-3-8-live-extended-thinking/).

**Gemini 4 Argon was announced September 30**, initially for trusted cyber defenders through **Fairwind**. This is a major family update, but the launch page does not establish general API availability or a public architectural blueprint. Its headline **1M-token output limit** should not be relabeled as an input-context specification. [Argon announcement](https://blog.google/innovation-and-ai/models-and-research/gemini-models/gemini-4-argon/).

**Catch-up:** **Gemini 3.8 Flash / Flash Cyber launched September 2**, with Flash aimed at general agent workloads and Cyber using trusted access. [Release](https://blog.google/innovation-and-ai/models-and-research/gemini-models/3-8-flash-and-3-8-flash-cyber/).

### GLM: distinguish a new base from more post-training

**GLM-5.3**, announced **August 14**, reuses the GLM-5.2 base; Z.ai explicitly attributes its gains to scaled post-training. **GLM-5.3-Flash** instead starts from a new multimodal base, combining sparse and linear attention with **manifold-constrained Hyper-Connections (mHC)**. Its released configuration is **320B total / 18B active**, trained on a reported **30T-token multimodal corpus**, with MIT weights. Both are catch-up entries here. [5.3 announcement](https://z.ai/blog/glm-5.3), [official repository](https://github.com/zai-org/GLM-5), [Flash model card](https://huggingface.co/zai-org/GLM-5.3-Flash).

Z.ai's **September 17** article details the inference infrastructure behind Flash, including disaggregated encoding/prefill/decoding and cache optimizations. It is useful systems evidence, but should not be dated as a new Flash checkpoint launch. [Infrastructure disclosure](https://z.ai/blog/glm-built-its-inference-infrastructure).

## 8. Architecture changes worth tracking

This comparison is the report's synthesis of the linked disclosures. Some designs predate the reporting window and are included to repair gaps in the survey.

| Question | Major-family example | What changes |
|---|---|---|
| Can input processing cost less than output generation? | [DeepSeek V4.1-Flash](https://arxiv.org/abs/2609.19969) | Causal encoder–decoder with different active compute for prefill and decode. |
| Can long context use a mixture of compressed state and selective retrieval? | [Qwen3.8-Flash-Next](https://arxiv.org/abs/2608.30320), [GLM-5.3-Flash](https://github.com/zai-org/GLM-5) | Hybrid linear and sparse attention instead of full attention at every layer. |
| Can capacity grow without proportional per-token computation? | [Qwen Flash-Next](https://arxiv.org/abs/2608.30320), [DeepSeek V4.1](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash) | N-gram lookup embeddings / Engram conditional memory supplement MoE capacity. |
| Can information move differently across depth? | [Kimi K3](https://huggingface.co/moonshotai/Kimi-K3), [Hy4](https://huggingface.co/tencent/Hy4-preview) | Attention Residuals / iHC change layer-to-layer information flow. |
| Does a better closed model imply a documented new architecture? | GPT-6/6.1, Claude 5.5, Gemini 4 Argon | No internal redesign is established by the reviewed release announcements; record capabilities and access separately. |

**Interpretation:** efficiency-oriented architectural changes are now present in major released families. They extend the survey beyond “vision encoder + language model” diagrams, but do not imply that vision encoders have disappeared. DeepSeek V4.1, Kimi K3, and Qwen Flash-Next all explicitly retain visual encoding components in their disclosures.

## 9. Survey corrections and next comparison

The catalogue should distinguish **release date, paper date, checkpoint availability, and API routing**. In particular, this report corrects or fills gaps around GPT-6 Astra, Claude Fable/Mythos 5.1, Qwen Flash-Next, DeepSeek V4.1, Kimi K3's released weights/encoder, Hy4, and GLM-5.3-Flash. The main VLM table includes models with verified visual capabilities; Hy4 remains in this family report as a language-model architecture reference.

For a meaningful follow-up comparison, prioritize document/chart understanding, image/video reasoning, computer use, and latency/cost under matched settings. Record model snapshot, input resolution, context length, reasoning budget, tools, and evaluation harness. Image generators belong in a generation/editing comparison; a language-only model or a restricted-access announcement should not silently enter a VQA leaderboard.

**Secondary research watch:** [LoopVL](https://arxiv.org/abs/2609.38426), [Gestalt](https://arxiv.org/abs/2610.00576), [Long-WAM](https://arxiv.org/abs/2610.10528), and [Liquid AI d1](https://huggingface.co/blog/LiquidAI/open-d1) remain relevant research leads. They are outside the main release comparison in this report.
